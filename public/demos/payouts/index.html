Enablement Reference

There's no test-card matrix for this one — the gate is account configuration, not input data. This panel documents what's required and what failure looks like instead.

1. Credits Enabled — checked on this merchant account in the internal gateway admin tool (Options section). Not a Control Panel self-service toggle.
2. Role permission — Settings → Team → Manage Roles → the role issuing the credit needs "Create Credits without a Previous Transaction" checked, under Transactions.
3. Processor support — some processors reject credits outright regardless of the above (PayPal always does, with error 91546). Confirm your processor allows it.
If Credits Enabled isn't set, expect a gateway-level rejection — check the diagnostics panel's raw response for the specific validation error rather than a generic "declined."
Confirmed by testing all four types: Card is the only payment method that supports detached credit. PayPal, Venmo, and ACH (US Bank Account) all reject identically with 91546 — Credits are not supported by this processor. Detached credit is fundamentally a card-network (Visa/Mastercard reversal rules) mechanism — PayPal/Venmo route through PayPal's own rails instead of card networks, and ACH's NACHA rails have no equivalent "blind credit" concept either. If you need to send money to a customer's bank account or PayPal/Venmo balance outside a prior sale, this API isn't the path — that would need a different product entirely (e.g. PayPal Payouts, a separate API).
Card network rules generally prohibit sending funds to a card with no corresponding sale. Braintree enables this only for reviewed use cases (processor migrations, gaming/RMG payouts under compliance agreements) — and recommends leaving it enabled only for the shortest window actually needed, since a compromised account with credits enabled can move money to any vaulted method with no purchase to point back to.
